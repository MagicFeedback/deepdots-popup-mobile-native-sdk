# Changelog

All notable changes to the Deepdots Popup SDK are documented in this file.

## 0.5.0 - 2026-08-14

Parity with Popup Web SDK 1.5.0 for everything that applies to the native
(Compose) chrome.

### Added

- **`InitOptions.showProgressBar`** — a `Question X of Y` label with a progress
  bar under the popup header. `null` (default) follows the `showProgressBar`
  configured for the survey in the platform; `true` / `false` force it. It also
  respects the survey's `progressUnit` (question count or percentage),
  `showProgressUnit` and `loadingBarColor`, and stays hidden on the start
  screen, on the completion screen, and when the survey has a single page.
  - Logic lives in `ui/ProgressBarState.kt` as pure functions so it is unit
    tested the same way as on Web.

### Fixed

- **The Back button never appeared when the next screen was a dynamic
  follow-up question.** The previous check was `total > 1 && progress in 1
  until total`, and follow-ups are not part of the page graph: they add 0.5 to
  `progress` and leave `total` untouched, so a single-question survey with a
  follow-up never satisfied it. Navigation state is now driven by how many
  pages the user has actually advanced. A validation or submit error no longer
  forces the "next" state either — it recalculates from that depth.
- **The survey's completion screen showed a generic message instead of the one
  configured in the platform.** The survey WebView now passes
  `addSuccessScreen:false` and renders `style.successMessage` itself, so the
  thank-you screen appears as designed, image included. Previously it was drawn
  by `renderSuccess` in `@magicfeedback/native`, which uses `textContent` (so
  HTML from the platform's editor could never render) and falls back to a
  literal that ignores the survey's style.

### Not included

- **`surveyCss`** (host-supplied CSS for the survey), added in Popup Web 1.5.0,
  is not ported: the native chrome is Compose rather than HTML, so there is no
  popup stylesheet to inject into. Use the popup style from the platform
  (`theme`, `position`, `font`) for native.

### Distribution

- The Android **AAR is no longer versioned in the repository**. It had been
  frozen at 0.2.2 while 0.3.0, 0.4.0 and 0.5.0 shipped, so anyone taking it
  from the repo got stale code. It is now published as a GitHub Release asset,
  with Maven Central remaining the primary channel
  (`scripts/prepare_maven_upload_zip.sh`).

### Release follow-ups

- Upload the signed Android bundle to Sonatype Central Portal.
- Build `DeepdotsSDK-0.5.0.xcframework.zip`, attach it to the `0.5.0` release of
  `MagicFeedback/DeepdotsSDK-SPM`, and bump `spm/Package.swift` — it still
  points at **0.3.0**.

## 0.4.0 - 2026-08-05

### Migration

- **Analytics events generated by the SDK are now prefixed `deepdots_`**
  (`deepdots_page_view`, `deepdots_session_start`, `deepdots_message`, …).
  Anything consuming these events downstream — dashboards, BigQuery queries,
  warehouse models — must be updated to the new names. Events you send with
  `track(name, params)` are unaffected.
- **`onBackground()` is now the end of an analytics session**, not just a flush.
  Call it from `Activity.onStop` / `applicationDidEnterBackground` only. Do
  **not** call it from `onPause` / `willResignActive`: on iOS the `inactive`
  state is transient (an incoming call, the app switcher) and would split one
  session in two. `onForeground()` opens a new session.

### Added

- **Custom font for the native chrome and the survey.** `PopupStyle.font`
  (`family` plus an optional `url`) now applies to the popup title, buttons and
  form controls as well as to the survey inside the WebView. Fonts are fetched
  once and cached per session; `family` is sanitized and a `url` is only
  accepted over `http(s)` / `data:`.
- **`InitOptions.renderChrome`** — default `true`. With `false` the popup
  renders without the scrim and the card so the host controls the visual frame.
  The survey stays fully functional. Note that on native the SDK still mounts
  the full-screen overlay itself; the flag removes the scrim and card, it does
  not hand the container over.
- **Crash reporting.** `reportError()` plus managed handlers
  (`UncaughtExceptionHandler` on Android, `NSSetUncaughtExceptionHandler` on
  iOS). Crashes are queued and replayed on the next launch. The iOS handler
  deliberately does not chain to a previously installed handler; the limitation
  is documented in the source.
- **Messaging metrics.** `trackMessage()` emits `deepdots_message` for push and
  in-app funnels, guarded by `MessageGuard`: it drops unknown channels,
  duplicate `(message_id, stage)` pairs, and the same `message_id` appearing on
  two channels, which otherwise produced impossible conversion rates. A rejected
  call always logs why.
- **`trackMeaningfulInteraction()`** for Product Effectiveness metrics.
- **Session lifecycle and identity.** `endSession()`, `setUserId(id)` (closes
  the previous user's session before switching), and a final batch sent with
  `completed:true` so the backend can tell a session actually ended.
- **`setMetric(key, value)`** for host-measured values, sent in a dedicated
  `metrics` field.
- **Persistent storage by default.** `user_id` now survives app restarts with
  no host configuration (`SharedPreferences` on Android via an auto-captured
  application context, `NSUserDefaults` on iOS). Without it every launch
  counted as a new user. Hosts can still inject their own `KeyValueStorage`.
- **Device, language and geo context** in the analytics envelope, and
  `setContactAttributes()` for host-known user attributes.
- **Concurrent mini-services** — `exitMiniService(name)` closes the right one.

### Changed

- SDK console output is now in English throughout, matching the Web SDK.
- Delivery reliability for the analytics channel: `5xx`/`408`/`429` re-queue the
  batch, `4xx` is logged with status and body and discarded, and batches are
  serialized until the backend has assigned a `sessionId` (two parallel posts
  created two records). Delivery is therefore **at-least-once**, so the backend
  must deduplicate by `(user_id, event name, timestamp)`.

### Fixed

- **iOS simulator test and framework builds failed to link.** Inside
  `binaries.all` the `name` is the binary's (`debugTest`, `releaseFramework`),
  not the target's, so the "not simulator" guard never matched and
  `-mios-version-min` leaked into the simulator link, which `ld` rejects.

## 0.3.0 - 2026-06-01

### Migration

- **iOS framework renamed `ComposeApp` → `DeepdotsSDK`.** Update your import
  and re-select the package product:
  - `import ComposeApp` → `import DeepdotsSDK`
  - In Xcode, remove the old `ComposeApp` product from your target and add the
    `DeepdotsSDK` product from the Swift package.
  - Objective-C consumers: exported class prefix changed `ComposeApp*` →
    `DeepdotsSDK*` (e.g. `ComposeAppDeepdotsPopups` → `DeepdotsSDKDeepdotsPopups`).
  - Swift type names are unchanged (`DeepdotsPopups`, `InitOptions`, …).
- **Backend: popup event statuses changed** (see "Changed" below) — the API
  must accept `SHOWED` / `PARTIAL` / `COMPLETED` (upper-case); `opened` is no
  longer sent.

### Added

- **`PARTIAL` popup event reported to the API.** The SDK now posts a `PARTIAL`
  status (`POST /sdk/popups`) the first time the user answers a question and
  advances (first non-error `after_submit` from the survey). Only one `PARTIAL`
  is sent per survey; further answered questions do not re-post. Previously the
  `partial` progress path existed only for local cooldown logic and was never
  exercised by the live survey, so the backend never received it.

### Changed

- **Popup event statuses sent to the API are now upper-case and aligned with
  the cooldown enum.** `POST /sdk/popups` now sends `SHOWED` / `PARTIAL` /
  `COMPLETED` (matching the `SHOWED`/`PARTIAL`/`COMPLETED` values the API
  already returns in popup cooldown conditions). The "popup shown" event status
  changed from `opened` to **`SHOWED`**, and the completion status from
  `completed` to **`COMPLETED`**. **Backend must accept the new values.**
  - When each is sent: `SHOWED` on popup display (`showDefinition`), `PARTIAL`
    on first answered question (`recordSurveyPartial`), `COMPLETED` on survey
    completion (`completeSurvey`).

### Fixed

- **Survey popup unreadable in system dark mode (iOS).** When the host device
  was in dark mode the survey area rendered with a black background and
  near-invisible text, while the popup card header stayed light. Root cause:
  the survey is hosted in a `WKWebView` via Compose's UIKit interop, which
  punches a transparent hole in the Compose canvas; with a transparent WebView
  the host view controller's background (black in system dark mode) showed
  through — it was **not** a `prefers-color-scheme` / CSS issue. The survey
  WebView now paints the popup's themed background as an opaque color, so the
  survey area always matches the rest of the popup. The same opaque themed
  background is applied on Android as a precaution. Also pins the survey
  document to `color-scheme: light` and forces the iOS WebView's
  `overrideUserInterfaceStyle` to light so native form controls don't adopt
  dark styling.
  - `SurveyView` now takes a `backgroundColor` parameter
    (`SurveyView.kt`, `PopupView.kt`, `SurveyView.ios.kt`,
    `SurveyView.android.kt`, `MagicFeedbackHtml.kt`).

> Note: true dark-mode theming of the survey is **not** included — the
> MagicFeedback web form has no dark variant (its stylesheet has no
> `prefers-color-scheme` rules and uses light-assumed text colors), so a dark
> background would make the survey text unreadable. Real dark support is
> tracked separately and requires theming the survey content layer first.

## 0.2.2

### Added

- Built-in localization for the SDK's default button labels (Send / Cancel /
  Start survey / Complete survey / Back). `provideLang` now drives the
  fallback used when `PopupDefinition.actions` does not supply an explicit
  label. Supported locales: `en`, `es`, `da`, `no` (incl. `nb` / `nn`), `sv`,
  `fi`, `zh-CN` (incl. `zh-Hans`). Region tags (`es-ES`, `nb-NO`, `zh-Hans`)
  and underscore variants (`es_419`) are accepted; unsupported locales fall
  back to English. Host- or server-supplied labels still take precedence.
- Public read-only `DeepdotsPopups.environment: Environment` property so
  host apps can assert at runtime which backend their `publicKey` is
  hitting. Reflects the value passed in `InitOptions.environment` and
  defaults to `Environment.Production` before `init()` is called.

### Fixed

- Survey WebView popups now wrap the form container with the `deepdots-popup`
  CSS class. The official popup stylesheet scopes most input, select,
  textarea, radio and focus rules under `.deepdots-popup`, so without this
  wrapper Android (and iOS) WebViews fell back to the platform's default
  user-agent styles. Symptoms reported by integrators included text inputs
  showing the orange WebView focus outline and rating questions rendering as
  a native multi-`<select>` with the default blue selection highlight. With
  the wrapper in place all scoped rules now apply correctly.

### Changed

- Bumped bundled `@magicfeedback/native` from `2.1.7-alpha.9` to the latest
  stable `2.2.4`. The CDN URLs (jsDelivr and unpkg) and the three local
  fallback bundles (`shared/src/androidMain/assets/magicfeedback/`,
  `shared/src/iosMain/resources/magicfeedback/`,
  `iosApp/iosApp/magicfeedback/`) have all been refreshed.
- `example-android` now depends on `:shared` via `project()` instead of the
  published Maven artifact so unreleased SDK changes are exercisable in the
  demo without first publishing a snapshot.
- `example-android` Login screen exposes a language picker for all seven
  supported locales, and the Home top bar surfaces the active environment
  and language as a subtitle (`env=… · lang=…`).
- Translated remaining Spanish KDocs and inline source comments to English
  across the public `commonMain` surface so IDE hover documentation reads
  in English for SDK consumers. The internal example
  `ui/example-ts-renderPopup.ts` was translated as well.
- Added a clarifying KDoc to `DeepdotsPopups.markSurveyAnswered()` noting
  that the SDK invokes it automatically on survey completion; hosts do not
  need to call it manually in normal flows.

### Documentation

- Documented the i18n behavior and the new `environment` getter in the
  English, Spanish, and Danish quickstart pages, and added a "Diagnostics"
  entry to the API reference.
- Removed the internal `Storage` / `KeyValueStorage` option from the public
  documentation (quickstart, models reference, server-mode guide). The SDK
  is designed for server mode where frequency caps are enforced by the
  backend; the in-memory cooldown cache is an internal detail and is no
  longer surfaced as a configurable knob.

## 0.2.0

### Breaking changes

- `InitOptions.debug` no longer controls the backend base URL. It now only controls
  SDK log output. Integrations that relied on `debug = true` to point the SDK at
  `https://api-dev.deepdots.com` must now opt in explicitly via the new
  `InitOptions.environment` field.

### Added

- `Environment { Production, Development }` enum exposed from
  `com.deepdots.sdk.models`.
- `InitOptions.environment: Environment?` — controls the backend base URL.
  Defaults to `Environment.Production` (`https://api.deepdots.com`). Set
  `Environment.Development` to hit `https://api-dev.deepdots.com`.

### Changed

- `SdkRuntime.env` is now derived from `InitOptions.environment` instead of
  `InitOptions.debug`. Combinations like `debug = true` with
  `environment = Environment.Production` now correctly emit SDK logs while
  talking to the production backend.
- Android and iOS demos (`example-android`, `example-android-local`,
  `iosApp/DeepdotsDemo.swift`) updated to set
  `environment = Environment.Development` so they keep pointing at the dev
  backend.
- Documentation (quickstart, server-mode guide) updated for English, Spanish
  and Danish to reflect the new field and the decoupling of `debug` from the
  environment.

### Migration

If you were relying on `debug = true` to hit the dev backend, add the new
field explicitly:

```kotlin
val options = InitOptions(
    debug = true,
    environment = Environment.Development,   // previously implied by debug = true
    mode = Mode.Server,
    popupOptions = PopupOptions(publicKey = "<your-public-key>")
)
```

To talk to production while keeping SDK logs on (previously impossible):

```kotlin
val options = InitOptions(
    debug = true,                            // logs on
    environment = Environment.Production,    // (or omit — it's the default)
    mode = Mode.Server,
    popupOptions = PopupOptions(publicKey = "<your-public-key>")
)
```
